# Markdown conventions

Tone: write like a personal note. Objective, informative, direct. State facts, record decisions, move on.

- No em-dashes (`—` or ` — `). Use two sentences, a comma, semicolon, colon, or parentheses.
- No contrast framing (`not A, but B` / `It wasn't X. It was Y.`). State what something *is*, drop the negation.
  - ❌ "The engine is not a WordPress component. It is a pure PHP class."
  - ✅ "The engine is a pure PHP class with zero WordPress dependency."
- No hedge openers. Delete the wrapper, keep the content. Banned: "It's worth noting", "It's important to understand", "At its core", "To put it simply", "When it comes to".
- No artificial repetition in lists. Collapse repeated words, drop dramatic phrasing.
  - ❌ "No WP dependency, no WordPress bootstrap, no plugin overhead."
  - ✅ "No WordPress dependency, bootstrap, or plugin overhead."
- Favor readability over choppy short sentences. Join related thoughts with proper structure.
  - ❌ "The engine parses HTML. It runs rules. It collects issues."
  - ✅ "The engine parses HTML, runs rules against the DOM, and collects issues."
- Minimize negations. Say what something *is* or *does*; prefer additions over negations.
